## Timing, causality and identity

One unchanged launch_contained call runs stdlib-only isolated Python with the
existing explicit allowlisted environment, no DB/model/imported adapter. The
target touches the baseline, emits a bounded nonce/PID readiness record and waits.
The observer binds the live PID to start_ticks/PPID/process-group and cgroup
membership, checking that only observer and child participate. Linux helper
poll() retains the process identity with WNOWAIT; no foreign wait/reap or PID kill
is introduced. Before gate the process identity is rechecked.

The same surviving observer samples t0 immediately before its nonblocking
one-byte G write. The child emits an attempt record naming the fixed increment
immediately before attempting allocation/touch, then either emits explicit
MemoryError denial, or frees a successfully touched increment and emits completion.
The observer samples t1 after receiving a terminal record, or immediately after
the same owned handle reports exit. Queued attempt bytes can be drained after an
observed exit without moving t1 backwards. Both endpoints use the observer's
time.monotonic_ns; child time is not compared or subtracted. Protocol and scheduling
overhead make this a conservative upper bound, not the true peak duration.

Before-gate and post-terminal memory.events are separately retained. `max` alone
never establishes OOM, kill or denial. A passing killed-attempt witness requires
all of: verified identity, ready gate, fixed attempted increment acknowledgement,
owned exit -9, positive post-gate oom_kill delta, elapsed upper bound <250ms and
confirmed cleanup. A passing denied-attempt witness requires an explicit target
MemoryError record and positive post-gate oom delta, in addition to the same
identity/timing/cleanup gates. Denial without correlated OOM evidence is unproved.
An exit -9 alone, stale/pre-gate counter, malformed/partial message or unrelated
participant cannot pass. No completed over-limit RSS is inferred from either
witness. The single known child script creates no subprocess or worker thread.
Final cgroup participants must remain a subset of the original observer/child pair.

Successful completion by itself is UNPROVED_CAUSE, even if reclaim occurred; this
candidate requires enforcement evidence, not just a legal burst. Missing attempt
or timing, elapsed>=250ms or ambiguous cause becomes an explicit unproved SKIP
after cleanup. Identity violation, invalid protocol/preconditions or failed stop
is a failure, never quarantine-as-PASS. The pure oracle cannot promote cleanup or
identity failure on the strength of timing/events.

## IPC and cleanup bounds

No receiver/background observation thread is added. Both observer pipe ends are
nonblocking; select waits are bounded by readiness/terminal deadlines. The child
emits at most3 JSON lines (each bounded1024 bytes); the observer rejects more than
3 records, oversized buffers, invalid PID/nonce/order and incomplete framing. A
child stdout write uses nonblocking os.write and fails on short/would-block writes.
The gate write is one nonblocking byte. Child post-result wait is bounded10s.

The test finally records available facts and calls existing _finish once even if
record_property fails. The existing helper owns termination, reaping and residual
tree proof. _finish failure remains a test failure and never authorizes retry.
No DB/result writes, model loads or product changes occur. Synchronous local
proc/cgroup reads and existing helper OS calls are not claimed to have a universal
kernel syscall wall-time guarantee; the enclosing disposable-container owner is
the external fallback boundary in the future execution plan.

## Observer death: future outside-container capture, not implemented survival

The pytest observer shares the512MiB cgroup and can itself be OOM killed. This
patch does NOT implement an outside-container observer or durable pre-death
timing journal. If it dies, no t1/JUnit is invented; any available child bytes,
partial log or cgroup event are insufficient for L1 PASS. Record UNPROVED_OBSERVER_DEATH
or incomplete execution in the external capture, not a fabricated pytest outcome.

Before any separately approved native execution, parent must prepare a reviewed
capture invocation that owns one fresh named disposable container by ID+nonce,
retains it until natural exit/timeout inspect, records exact image/source/command,
State.OOMKilled/ExitCode and observer outcome, and confirms terminal/removal state
for that owned container only. No `--rm` before terminal evidence capture. On
timeout, capture owner terminates only its owned container and records forced
cleanup, never natural OOM/timing success. No environment-value dump or host
process enumeration. This is design only; no capture wrapper change is included
or represented as implemented. Existing parent-OOM evidence need not be rerun and
does not fill missing L1 timing data. Supervisor death or unproved cleanup blocks
qualification and any next native attempt pending reassessment.
