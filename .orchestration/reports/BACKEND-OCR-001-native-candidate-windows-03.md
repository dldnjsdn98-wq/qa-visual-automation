## Authoritative API sources actually read

Fetched through the read-only in-app browser from Microsoft Learn on 2026-09-26 KST. These are live published pages, not commit-pinned GitHub sources; no repository ref or immutable historical revision is claimed. The excerpts below were present in the rendered pages. No network permission denial or alternate-route retry occurred.

1. [Process Creation Flags](https://learn.microsoft.com/en-us/windows/win32/procthread/process-creation-flags), page updated 2025-07-14. General rule: “They can be specified in any combination, except as noted.” DETACHED_PROCESS `0x00000008`: “the new process does not inherit its parent's console”; it “can call the AllocConsole function at a later time.” It cannot be combined with CREATE_NEW_CONSOLE. CREATE_NO_WINDOW `0x08000000` is ignored with DETACHED_PROCESS or CREATE_NEW_CONSOLE. CREATE_SUSPENDED `0x4`: the primary thread “does not run until the ResumeThread function is called.” EXTENDED_STARTUPINFO_PRESENT `0x80000` specifies STARTUPINFOEX; CREATE_UNICODE_ENVIRONMENT `0x400` specifies the Unicode block. Thus the proposed combination has no listed conflict; both contradictory console flags are absent.
2. [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), updated 2023-02-09. “To set extended attributes, use a STARTUPINFOEX structure and specify EXTENDED_STARTUPINFO_PRESENT.” Standard fields “are copied unchanged to the child process without validation”; caller must provide valid handles. Function “returns before the process has finished initialization.” Existing explicit `argv[0]`, writable command buffer and explicit non-null environment are retained. Successful creation is not successful DLL/Python initialization.
3. [UpdateProcThreadAttribute](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), HANDLE_LIST entry: “These handles must be created as inheritable handles and must not include pseudo handles”; “pass in a value of TRUE for the bInheritHandles parameter.” Existing three real child pipe/null handles, inheritable bits, `0x00020002` handle-list attribute and TRUE are retained; no pseudo process handle is added. This is separate from console attachment.
4. [STARTUPINFOW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/ns-processthreadsapi-startupinfow), STARTF_USESTDHANDLES `0x100`: standard-handle members apply, handles must be inheritable and bInheritHandles TRUE. It defines hStdInput/hStdOutput/hStdError independently of default console buffers. No DETACHED_PROCESS exclusion is stated for these fields. The documentation supports explicit redirected handles; the installed Python runtime's use of them still requires evidence.
5. [AssignProcessToJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-assignprocesstojobobject), updated 2021-10-13. After assignment the process is subject to Job limits; memory operations before assignment “are not examined.” Documentation explicitly describes creating a suspended process with CREATE_SUSPENDED before assignment for a security-limited Job. Nested assignment has hierarchy/UI-limit/session restrictions; failure stays unavailable, never enables breakaway. The proposed flag does not itself establish valid nesting. No blanket guarantee about the installed enclosing Job is inferred.
6. [Creation of a Console](https://learn.microsoft.com/en-us/windows/console/creation-of-a-console), updated 2021-12-30: “Console processes are not attached to a console if they are created using CreateProcess with DETACHED_PROCESS.” It explicitly permits later AllocConsole and AttachConsole. This is the rationale for W1; it is NOT a permanent ban on console creation and does not explain the previous CREATE_NO_WINDOW/conhost observation.
7. [SetProcessWorkingSetSizeEx](https://learn.microsoft.com/en-us/windows/win32/api/memoryapi/nf-memoryapi-setprocessworkingsetsizeex): HARDWS_MAX_ENABLE means “The working set will not exceed the maximum working set limit.” Working set is resident physical pages. Privilege requirements may apply when increasing bounds; failure must remain unavailable, without elevation. Same direct-process maximum/page rounding/flags remain. Job private commit is not substituted for RSS, nor does a direct hard WS prove a second process bounded.
8. [TerminateJobObject](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject), updated 2021-10-13: “Terminates all processes currently associated with the job,” including child Jobs; processes cannot postpone or handle termination. This is an ownership guarantee, not a documented wall-clock upper bound for the native API call or all observer queries.

Conclusion: authoritative sources are available and support static compatibility of the proposed flags/redirected handles/suspended assignment. They do not prove no conhost on this installed OS/Python build, absence of future native console calls, hard-WS continuity, or bounded native-call return latency.
