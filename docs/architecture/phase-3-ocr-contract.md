## 1. Operation and immutable inputs

Verification is explicit per Screenshot, NOT automatically scheduled by upload. A user requests one complete OCR+verification run. A fresh client_run_id means a fresh run/snapshot, including deliberate reruns; retrying the same ID never reruns or refreshes its inputs. No batch/autonomous processing, cancel endpoint, result edits or deletion in v1. Failed runs are retained; explicit retry after terminal failure is a new run. Same bytes/context under different run IDs are legitimate independent runs.

Atomic creation transaction on authoritative PostgreSQL primary, REPEATABLE READ: validate screenshot scope; read screenshot hash/size/dimensions/MIME/core IDs and locale code; resolve ordered current expected mapping and LEFT JOIN exact build/locale translations in that SAME MVCC snapshot; copy inputs and effective runtime/matching configuration; insert run and durable PENDING job together; commit before responding. Snapshot semantics are the database read snapshot established by the first MVCC data query in this transaction, not uploaded_at, worker claim or completion time. Concurrent catalog transaction may be wholly before/after this snapshot, never a mixed view. Existing mapping replacement is transactional and unchanged. No locks or edits to catalog rows are added solely to freeze inputs.

Copy each expected item: position, string_key_id, string_id, entry_id|null, expected_text:string|null, translation_status:present|missing. Present "" is distinct from missing/null. Duplicate string_id/mapping keys remain forbidden by existing catalog; DIFFERENT keys with identical text remain separate expected occurrences. Preserve raw scalar Unicode exactly; no fallback locale/build or inferred missing text. Snapshot maximum 1000 items, each existing text limit10000 scalars, total JCS UTF8 snapshot <=8MiB; reject with 422 SNAPSHOT_LIMIT_EXCEEDED before any run/job commit rather than truncate.

Store snapshot_version=1, captured_at=transaction_timestamp(), source_mode="run_creation", screenshot facts, original locale_code and resolved OCR language, ordered expected items, counts. Snapshot digest is SHA256 of RFC8785 canonical JSON including those immutable fields (captured_at UTC six fractional digits). captured_at labels the transaction; snapshot visibility is defined above, not inferred from timestamp equality. Store canonical bytes and SHA256, validate hash when dispatching. Runtime profile/config digest likewise JCS. No legacy current expected-string endpoint changes; Web labels current catalog separately from this snapshot.

Copied historical string_key_id/entry_id are UUID audit values WITHOUT FKs to live key/entry rows: later permitted catalog edits/deletes must not destroy history or become newly forbidden. run has restrictive composite project/screenshot FK; snapshot joins results by run/project, never current catalog text.

## 2. Creation identity and API

## 3. Persistence and worker boundary

New additive migration owned03, never rewrite prior migrations. Suggested normalized tables:
- verification_runs: UUID id, project_id/screenshot_id restrictive composite FK; client_run_id UNIQUE(project_id,client_run_id); request fingerprint/version; immutable snapshot canonical bytes/hash and effective config canonical bytes/hash; lifecycle fields from Run; timestamps.
- verification_expected_items: project_id/run_id FK RESTRICT, position PK with run, copied key/entry/text/status; missing iff text/entry null; present permits empty. UNIQUE(run_id,string_key_id), position nonnegative.
- verification_jobs: run_id PK with scoped run FK, state PENDING|RUNNING|RETRY_WAIT|SUCCEEDED|FAILED; attempt_count0..3, generation>=0, attempt_token UUID|null, lease_expires_at|null, available_at, safe last error. Job is the durable queue/outbox: committed run always has exactly one job. No Redis/publish-after-commit dependency.
- ocr_results: id, project_id/run_id UNIQUE and scoped FK, immutable engine/profile/config snapshot, source hash/dimensions, coordinate version, raw output digest, region_count/no_text, actual runtime manifest and timings.
- ocr_regions: run/result scoped FK, stable region_index>=0 UNIQUE(result_id,index), raw text, required finite confidence, quadrilateral/polygon and original bbox, engine original index.
- verification_results: id/project/run UNIQUE, ocr_result scoped FK, snapshot/config hashes, normalization/matching versions, aggregate quality/evaluation reason, count summary.
- verification_items: result/run/expected_position scoped FK; expected text/key audit copied from snapshot, optional assigned region_index scoped same OCR result; match method/reason/score/status. UNIQUE(result_id,expected_position), partial UNIQUE(result_id,region_index) when nonnull enforces one-to-one.

FKs/constraints enforce project/run/result scope, score0..100/confidence0..1 finite and positive valid bbox; no floating NaN. Status consistency: results exist iff SUCCEEDED, completed_at iff terminal, RUNNING requires lease/token, terminal no lease; transactional service ownership coordinates duplicated run/job status with enforced tests. DB column states not merely frontend conventions. Index jobs(state,available_at) and RUNNING lease expiry; runs(project_id,screenshot_id,created_at DESC,id DESC). No result blob image copy; original storage objects immutable/read-only.

Owner03 provides backend-owned runner/persistence service (e.g. python -m backend.app.workers.ocr), polling DB every2s when idle; 05 provides pure OCR/matching adapter under worker/ocr and worker/verification, no direct DB/storage mutation or public internal claim endpoint. Same trusted deployment privileges as existing Backend; no new authentication/security setting change. Parent runner supplies verified bytes/snapshot/profile, owns heartbeat and all commits. Interfaces are versioned Python data objects/dicts described by this contract, no shared code file assigned implicitly. 03 and05 coordinate adapter interface tests; pyproject sole editor03 after PM claim.

Claim short READ COMMITTED on PRIMARY: select due PENDING/RETRY_WAIT or expired RUNNING using FOR UPDATE SKIP LOCKED; recheck DB clock_timestamp() after row lock; increment attempt_count and monotonic generation, fresh UUID token, lease=now+60s, status RUNNING/stage OCR. Commit before work. The runner is configured for the registry's deployable profiles; after claiming it verifies capability/model readiness. Removed/unavailable profile becomes FAILED MODEL_UNAVAILABLE rather than being silently skipped forever. Max3 claims including crashed attempts; expired third attempt ->FAILED RETRY_EXHAUSTED under lock, no fourth inference.

Renew <=20s, predicate RUNNING plus generation/token and lease>fresh DB time, extend60s. Equality expired; expired worker cannot revive itself. Separate heartbeat connection, no transaction held during decode/inference/matching. Uncertain renew/DB failure stops finalization; supervise child and discard local output. Whole-attempt timeout300s including inference+matching; terminate/join owned child, never kill user services. Failed stop/liveness keeps resources quarantined locally and prevents uncontrolled child publication (child has no DB write authority). Process-crash resumption repeats computation using same immutable inputs; different generation cannot write final results.

Stage VERIFY may be updated with a short fenced transaction, but OCR provisional regions stay private/in-memory/temp. No public partial successful OCR result on a verification error in v1. Finalization transaction locks job, validates current unexpired generation/token; validates complete bounded adapter output and snapshot/profile digests; inserts OCR/result/regions/items AND updates run+job SUCCEEDED atomically, clears lease/error and sets completed_at. Row lock held through commit; expiry during short already-validated commit cannot permit concurrent takeover. Partial insert/validation failure rolls back all results.

Creation serialization/deadlock conflicts (SQLSTATE40001/40P01) roll back the entire creation transaction and retry at most3 times with the same request K; each rolled-back snapshot is discarded, only the committed snapshot is authoritative. Exhaustion503. Conflicting existing-K checks may require a fresh transaction after unique-key wait so a stale REPEATABLE READ snapshot never becomes an absence claim.

Known retryable failure commits RETRY_WAIT under same fence with next available now+5s after attempt1, now+10s after attempt2 (DB clock); after third terminal FAILED RETRY_EXHAUSTED with causal code. No unbounded retries or local clock authority. Nonretryable engine/config/invalid-output errors FAILED immediately. Cancellation/process death leaves RUNNING for lease takeover; no marks from stale token. Ambiguous claim/final commit: invalidate connection; fresh locked primary read resolves surviving transaction; if cannot resolve return/log uncertainty and perform no mutation. Unique run/result constraints and fencing permit at-least-once computation with at-most-one committed result set, not exactly-once engine execution.

## 4. Input integrity, errors, bounds and profiles

Runner opens the original once through the existing scoped Storage abstraction into a bounded immutable byte buffer, verifies SHA256 and size of that same buffer against the snapshot BEFORE decoding each attempt, and passes those exact bytes to OCR (no second path open). Missing/read-unavailable ->INPUT_STORAGE_UNAVAILABLE retryable; same-length/hash corruption ->INPUT_HASH_MISMATCH nonretryable + alert; do not overwrite/delete original or receipt. Existing image limits (20MiB/40M pixels/single frame/16384 axes) remain. Invalid original decode ->SOURCE_DECODE_ERROR nonretryable. Terminal run does not alter screenshot or upload receipt.

Failure classes:
- ENGINE_UNAVAILABLE/MODEL_UNAVAILABLE: nonretryable worker environment issue (profile readiness should prevent initial queue); no silent fallback/download.
- ENGINE_TIMEOUT and transient storage/engine process crash: retryable max3.
- ENGINE_OUTPUT_INVALID/RESULT_LIMIT_EXCEEDED/NORMALIZATION_ERROR: nonretryable.
- SNAPSHOT_INTEGRITY_ERROR/PROFILE_DIGEST_MISMATCH/INPUT_HASH_MISMATCH: nonretryable integrity alert.
- DB outage: cannot truthfully persist a state; retain lease/last state, recover via primary fence, never quality FAIL.
- No text: successful OCR with zero eligible nonempty normalized region texts and no_text=true; not ENGINE_ERROR.
Unknown child exceptions: ENGINE_INTERNAL_ERROR nonretryable safe code, diagnostic private; no leaked traceback.

Profile manifest immutable by profile_id and hash: engine/library versions, model artifact names and SHA256s/licenses, language map version, preprocessing/detector/recognizer thresholds, RGB decoding policy, CPU/device/thread settings, seed/determinism limitations, Unicode/runtime/RapidFuzz versions, normalization and matching IDs. Active deployment must retain pinned profiles/models for existing runs; unavailable is explicit failure, never repoint profile id. New model/version requires new profile id, new run for comparison. Stored completed result carries actual manifest matching requested profile; actual hardware/runtime differences recorded and rejected if outside profile allowance. No implicit network download from worker. Installation/weights exact versions and hashes are implementation evidence from05+03 before READY_FOR_REVIEW, not invented here.

Locale resolution uses screenshot's immutable Locale row code at snapshot, not guessed image language. Preserve raw code; accepted OCR tag mapping is profile manifest's explicit case-insensitive table after replacing "_" with "-" ONLY for lookup. No update of stored Locale code. No generic fallback to English or script guessing. Mapping must explicitly distinguish zh-Hans/zh-CN and zh-Hant/zh-TW; ambiguous zh is unsupported unless profile explicitly declares one reviewed mapping. ja/ja-JP, ko/ko-KR, en/en-US/en-GB supported only when exact profile table includes them. Unsupported ->422 OCR_LOCALE_UNSUPPORTED before enqueue; mappings are pinned in snapshot/profile and remain stable on retries.

Output bounds per run: <=1000 OCR regions, <=10000 Unicode scalars per region, <=1MiB total UTF8 raw region text, complete serialized adapter result <=8MiB, expected snapshot bounds above. No truncation/selecting convenient regions to pass limits: FAILED RESULT_LIMIT_EXCEEDED. Matching real-pair count <=65,536; aggregate normalized scalars <=1,000,000; sum(len(expected)*len(region)) over fuzzy pairs <=50,000,000 as a deterministic distance-work budget. Exceeding any bound is FAILED RESULT_LIMIT_EXCEEDED; no greedy fallback. Total matching deadline is part of attempt300s. No text filtering by confidence after engine output except profile-pinned detector/recognition behavior; discarded engine proposals must be counted in runtime diagnostics.

## 5. Coordinates and OCR region semantics

Authoritative coordinate space original-raster-v1: decoded stored raster width/height from existing Screenshot, BEFORE EXIF auto-orientation. Original bytes/hash/dimensions unchanged. Decode without automatic EXIF transpose; runtime manifest records EXIF orientation and policy ignored-v1. Web overlay must use the same raster orientation; browser auto-oriented display is not a coordinate authority. Use canvas/ImageBitmap decoding with tested no-orientation handling or separate explicit transform to raw raster; if a browser cannot guarantee it, show coordinates/table and omit overlay with a visible unsupported-orientation notice, never place misleading boxes.

Origin top-left, x right, y down. Continuous pixel-edge coordinates x in[0,W], y in[0,H]; boxes half-open [x,x+width) etc. Adapter records invertible 3x3 homogeneous transform T mapping original edges to inference edges, including resize/letterbox/crop/rotation; use inverse T on EVERY polygon vertex. No transform inferred solely from final dimensions. v1 default preprocessing only uniform resize+padding, no automatic crop/rotation; alternative profile must pin explicit matrix pipeline and numeric tests. Singular/nonfinite transform ->ENGINE_OUTPUT_INVALID.

Engine quadrilateral transforms to original convex polygon; vertex order clockwise in screen coordinates, rotate order to lexicographically smallest(y,x), no self-intersection. Original polygon coordinates finite and stored at six decimal places using round-half-even. Intersect the transformed convex polygon geometrically with rectangle[0,W]x[0,H] (Sutherland-Hodgman or equivalent), never independent vertex clamping; persist clipped:boolean and raw transformed polygon for audit. Fully outside/nonpositive-area/self-intersecting input is invalid. Canonical clipped polygon has3..8 vertices; remove repeated closing/consecutive duplicate vertices after six-decimal rounding, normalize -0 to0 and revalidate nondegenerate area. Bbox={x:floor(minx),y:floor(miny),width:ceil(maxx)-x,height:ceil(maxy)-y} from clipped unrounded polygon; require0<=x<W,0<=y<H,positive width/height and extent<=W/H. Collapsed/degenerate polygon invalid. Preserve engine raw polygon/transform in audit metadata; authoritative UI/matching coordinates are original values. No image-space percentage confusion.

A region is exactly one engine text-line unit after adapter mapping, no concatenation/splitting/grouping or text deduplication in v1. Preserve duplicates even same text/geometry. text is exact engine Unicode string after shared persistable-scalar check; do not trim/normalize raw text. Empty text regions retained but excluded from matching, reason EMPTY_OCR_TEXT. confidence is required finite[0,1], including valid0/1, from pinned recognition-confidence semantics; missing/out-of-range/nonfinite is ENGINE_OUTPUT_INVALID. An engine percentage is divided by100 only when that conversion is explicitly pinned in the adapter profile. Do not invent1 or rescale unknown scores. Quality match_score is separate, never multiply by OCR confidence.

Order regions by original bbox(y,x,height,width), then canonical polygon JCS bytes, raw text UTF8 byte order, then engine emission ordinal as final tie; assign region_index0..n-1. Identical detector outputs may differ in emission ordering across engine versions; profile/actual engine pinning and stable final ordinal make each run's order reproducible. This is geometric display ordering, not a language reading-order claim for RTL/vertical text; matching does not concatenate neighboring lines.

Numeric examples: original800x600 resized0.5 with padding(10,20), T=[[.5,0,10],[0,.5,20],[0,0,1]]. Inference rectangle vertices(60,70),(160,70),(160,95),(60,95) -> original(100,100),(300,100),(300,150),(100,150), bbox100,100,200,50. Clockwise90 rotation of raw W=800,H=600 maps (x,y)->(600-y,x); inverse (u,v)->(v,600-u). Raw rectangle x100..300,y100..150 -> rotated u450..500,v100..300 -> same original bbox after inverse.

## 6. Matching and evaluation

Raw exact compares Unicode scalar sequences, case/space/punctuation sensitive. Normalization norm-v1: Unicode NFC, convert CRLF and CR to LF, collapse each maximal Unicode White_Space property run to ASCII space, strip outer ASCII spaces. NFC Unicode data version is15.0.0 in norm-v1 (Python3.12); White_Space set is U+0009..000D,0020,0085,00A0,1680,2000..200A,2028,2029,202F,205F,3000. U+200B/U+FEFF are not whitespace and remain; no Python str.isspace extension. Unicode version pinned profile; no NFKC, accent removal, punctuation/digit deletion, casefold or locale-specific transliteration. Locale selects model only; default normalization identical across supported locales, avoiding Turkish I/CJK width/diacritic equivalence assumptions. Preserve normalized strings alongside raw in results. Any future locale-specific rule needs new normalization_version/profile, never silent runtime locale behavior.

For each expected nonempty present item and eligible nonempty normalized OCR region: EXACT if raw strings equal (score100), else NORMALIZED if normalized strings equal and nonempty (100), else FUZZY score=100*(1 - Levenshtein_distance(a,b)/max(len(a),len(b))) on normalized Unicode scalar sequences with insertion/deletion/substitution cost1. This is RapidFuzz Levenshtein.normalized_similarity with processor=None, NOT fuzz.ratio/token-set/partial match. Freeze matching_version=one-to-one-levenshtein-v1. If both normalized empty no fuzzy edge. Scores compared using exact integer numerator/denominator cross-multiplication against decimal thresholds; response decimal score rounded half-even to six places only for display, with score_numerator and score_denominator retained so no rounded threshold promotion.

One-to-one assignment across expected items ordered by snapshot position and OCR regions ordered region_index. Real eligible edges only when score>0 and score>=review_threshold. Add unique unmatched dummy per expected. Find global assignment maximizing lexicographic objective: (number EXACT, number NORMALIZED, number assigned real edges, sum floor(score*1,000,000)), then lexicographically smallest region-index vector in expected-position order (dummy sorts after every real index). This explicit priority reserves exact evidence before approximate matches; do not implement greedy row matching or independent best-per-key reuse. Compute each micro-score by integer division of the rational; sub-micro differences intentionally tie only in the assignment objective, while status thresholds still use full exact ratios. No floating tie instability; bounded sizes/deadline above, algorithm/library choice05 with conformance examples.

Assigned EXACT/NORMALIZED ->PASS (100); assigned FUZZY score>=pass ->PASS else REVIEW. Unassigned present/nonempty ->FAIL reason NO_MATCH, method NONE, score0, region null. Below-review similarity may be exposed only as optional diagnostic best_candidate (not assigned or counted); v1 omit it for deterministic minimal API. Extra unmatched OCR regions stay visible, do not independently fail the result; no assertion of full-screen expected inventory.
Missing translation ->UNVERIFIED reason MISSING_TRANSLATION, score/method/region null. Present raw empty string ->UNVERIFIED EMPTY_EXPECTED; present whitespace that normalizes empty ->UNVERIFIED NORMALIZED_EMPTY_EXPECTED. Do not claim that a global empty expectation proves absence of text in a region. Such items consume no OCR region.
No expected mapping ->completed UNVERIFIED NO_EXPECTATIONS. No OCR text with evaluable expected items ->those items FAIL NO_MATCH (observable unmatched text), OCR itself SUCCEEDED/no_text. Engine failure ->run FAILED, no verification items/quality status.

Aggregate: if any evaluable FAIL ->FAIL; else if any REVIEW ->REVIEW; else if any UNVERIFIED or zero evaluable items ->UNVERIFIED; else PASS. Expose evaluated_count/unverified_count/pass_count/review_count/fail_count/unmatched_region_count so partial success never appears full PASS. A known FAIL plus missing translation remains FAIL with incomplete=true, never loses missing diagnostics. confidence is displayed only, not silently thresholded into quality.

Examples:
- expected k1="Play",k2="Play"; one OCR "Play": k1 gets region0/PASS by deterministic tie, k2 FAIL; two OCR duplicates ->two distinct PASS assignments.
- expected "é", OCR "e\u0301": NORMALIZED/PASS; raw values retained.
- expected "A", OCR "a": FUZZY score0 ->NO_MATCH FAIL. Fullwidth "Ａ" vs "A" not normalized equal.
- expected null missing, "" present, " \n" present ->three UNVERIFIED reasons, no region consumption.
- expected length20 with one substitution ->95 PASS; length20 with three substitutions ->85 REVIEW; four ->80 FAIL/unmatched.
- expected absent set + OCR zero ->UNVERIFIED NO_EXPECTATIONS, not PASS.
- current catalog edited after creation: completed items still use snapshotted text; new explicit run captures new text.

## 7. Web and backward compatibility

Screenshot schema/upload/list/current expected endpoints unchanged. Detail adds explicit Run verification action, profile availability selection and optional thresholds, run history and selected-run result view. Generate client_run_id once per explicit submit, retain across ambiguous response/retry until known outcome; do not auto-generate another ID on transport error. A deliberate rerun obtains new ID, clearly captures current catalog again.
Show processing PENDING/RUNNING/RETRY_WAIT/FAILED separately from quality badges. ### 10.1 Retention, schema and state completion

Snapshot copies storage_key privately, file_hash, file_size, media_type, width/height, project/build/locale/category/situation UUIDs, metadata_version and metadata, plus the current display name/code of each context row where the existing model supplies one. All are read in the same creation MVCC snapshot. These copied context IDs, like copied key/entry IDs, have no new FK to mutable catalog; the scoped restrictive Screenshot FK preserves provenance. No API returns storage_key. Snapshot corruption or missing rows fails SNAPSHOT_INTEGRITY_ERROR; never reconstruct from current catalog. Gaps in nonnegative expected positions are valid; preserve positions and sort ascending, never renumber them.

Client UUIDv4 accepts ordinary UUID text case-insensitively, emits canonical lowercase hyphenated form. Same-ID reservation, snapshot, run, attempts and results are retained indefinitely in v1; there is no TTL, cleanup/delete endpoint or job cancellation. A new run is associated through screenshot_id and its own new client_run_id; no rerun_of field or parent-run inference in v1. User history is the complete lineage. Project/Screenshot deletion must fail while referenced by a run. No Phase2 rows are backfilled or modified. A future retention policy requires a new reviewed contract.

Add verification_attempts: project_id/run_id/generation composite identity, claim_request_id UUID UNIQUE, attempt_token, claimed_at, lease_at_claim, outcome STARTED|SUCCEEDED|RETRY_WAIT|FAILED|EXPIRED and safe error/correlation fields. Initial STARTED may be closed once in the same fenced transaction as run transition; thereafter immutable. Expired takeover closes the predecessor as EXPIRED under the job lock before creating a new attempt; attempt3 expiry creates terminal RETRY_EXHAUSTED and no fourth attempt. Job keeps current mutable state, attempts keep prior evidence.

Append-only enforcement is database triggers in the additive migration for immutable run input columns, snapshot rows, profiles, completed attempts and all result/region/item rows. Reject UPDATE/DELETE of those fields/rows; allow only specified mutable lifecycle columns and STARTED attempt closure. Result insertion is restricted to the Backend finalization service and all inserts plus success commit share one transaction. Tests must cover direct SQL attempted mutation and cross-scope/result uniqueness. This does not claim tamper resistance against a database superuser. No account/privilege reconfiguration is needed.

| --- | --- | --- | --- |
| absent | committed valid POST | PENDING | attempt0; no lease/error/results/quality; stage QUEUED |
| PENDING / due RETRY_WAIT | locked claim | RUNNING | count+1, new generation/token; stage OCR; next_attempt_at null; current error null |

Correlation ID is generated by the parent for each attempt and retained in its safe error; no external tracing system required.

### 10.2 Transaction bounds and ambiguity resolution

All job mutations (including stage, renew, fail, retry, attempt-close and finalize) lock the job on the primary and recheck status/generation/token and lease strictly greater than fresh clock_timestamp. Reaper/takeover instead requires lease <= clock_timestamp under the lock; expiry is not an unfenced worker operation. Use lock_timeout=5s, statement_timeout=10s and idle_in_transaction_session_timeout=10s locally. Keep DB work short; generation is signed bigint starting0, fail closed JOB_GENERATION_EXHAUSTED before overflow under recovery lock. No wraparound. A transaction error always rolls back its complete state change.

Generate claim_request_id/token before claiming and durably insert that identity with the claim. Lost claim acknowledgement: close invalid connection, open a fresh primary transaction and lock that specific job; inspect its attempt identity, generation and current unexpired lease. Resume only if the exact committed claim still owns it. If a different claim won or the job is terminal, discard local work. If absence is proven after the original transaction has resolved, a new claim may be attempted; no inference based on an unlocked stale read. No public endpoint exposes claim tokens.

Renew ambiguity suspends work/publication until the same fresh-primary locked check confirms the committed live fence; otherwise terminate/discard the owned child and leave recovery to the durable lease. Finalize ambiguity resolves under the locked primary job: SUCCEEDED plus complete same-run result identities means committed success; live same fence with no results means the resolved prior transaction did not commit and a bounded retry of finalization is possible; stale/expired/terminal-other means discard. If the primary cannot resolve the transaction, retain uncertainty and do not commit failure. Enqueue ambiguity uses same-ID unique arbitration as section2, not an absence check. Each short operation permits at most3 attempts for definite 40001/40P01 rollback; unresolved outcome is never retried as a fresh identity.

Source read/verify/decode, model startup, OCR and matching all fit the 300s attempt budget. At most one child per runner process, one inference CPU thread in the baseline profile; scale via independent runner processes after resource measurement. Baseline child RSS budget is 2GiB; parent supervisor terminates a child exceeding that budget with ENGINE_RESOURCE_LIMIT (nonretryable). If the target OS cannot enforce/observe this bound, that profile remains UNAVAILABLE. Model startup and offline digest verification are included in runtime qualification. No automatic lower-tier model selection after timeout/resource failure.
